# Achados da auditoria

Base `d6169205` · 11/11/2026. Os IDs desta tabela são referências para retomar a investigação.

| ID | Prioridade e evidência | Local e evidência | Impacto, causa e ação |
|---|---|---|---|
| A01 | P0 · CONFIRMADO | GCP `speedbikers-prod` com billing desativado. API pública do Cloud Run retornou 503 duas vezes em `/health`. Cloud Scheduler e Tasks reportaram `BILLING_DISABLED` | API indisponível pelo caminho consultado, processamento assíncrono sem verificação de atividade. O responsável pelo faturamento precisa restabelecer o vínculo e conferir cada serviço, fila e execução recente |
| A02 | P0 · CONFIRMADO | MCP reportou Dev e produção `INACTIVE`. SELECT leve de catálogo falhou em ambos. A CI de `d6169205` falhou ao vincular Dev com `project is paused` | Acesso ao banco e aplicação de migrations bloqueados no ambiente observado. Confirmar no painel o estado de cada projeto e restabelecer o necessário à operação |
| A03 | P0 · CONFIRMADO no manifesto e lockfile | Next.js 16.3.8 acionava dois avisos críticos e um alto. Zod 4.4.3 acionava um alto. A Vercel identificou `d6169205` como origem do alias de produção | Versões vulneráveis exigem atualização. A explorabilidade de cada condição em produção e exploração real exigem evidência própria. Correção local em Next.js 16.4.1 e Zod 4.6.6. A auditoria voltou a passar no corte alto |
| A04 | P1 · CONFIRMADO por teste | `apps/api/src/shopee-push.ts`, `POST /push/shopee`, `packages/observability/src/logger.ts`. O corpo recusado fornecia nomes de campos e `code` sem validação. JSON profundamente aninhado retornava 500 em teste. Cancelamento assinado também escrevia `data` inteiro | Controle externo de conteúdo e volume por log e risco de exposição do payload. Correção local mantém o diagnóstico com nomes conhecidos e código numérico, descarta `data` e preserva o ACK e o comportamento de filas |
| A05 | P1 · CONFIRMADO pelo fluxo de escrita | `apps/api/src/shopee-shops.ts` e `tiktok-shops.ts` conferem o dono antes de `upsert` com `organization_id` por chave global | Callbacks válidos simultâneos para a mesma loja ausente podem cruzar titularidade e credenciais. Implementar uma transação com verificação do dono no conflito, persistência atômica e teste concorrente |
| A06 | P1 · CONFIRMADO pelo fluxo de retry | `apps/api/src/support-reply.ts` insere `PENDING` antes de enfileirar. Repetição com o mesmo ID responde `in_flight` mesmo quando a criação da tarefa falhou. `send-support-reply.ts` ignora o resultado de parte das atualizações terminais | A tentativa pode ficar pendente sem tarefa ou sem estado final conhecido. Testar falhas ambíguas e reutilizar chave estável e escopo persistido antes de corrigir a reconciliação |
| A07 | P1 · CONFIRMADO no GitHub | A API de proteção devolveu 404 `Branch not protected` para `main` e a consulta de regras devolveu `[]`. O alias de produção da Vercel acompanha a `main` | A publicação pode ocorrer sem um check obrigatório na ref. Configuração do GitHub precisa ser revisada com o responsável. O workflow de migrations tem dois gates separados no ambiente `producao` |
| A08 | P2 · NECESSITA INVESTIGAÇÃO | [Banco](DATABASE_MAP.md) e [candidatos](CLEANUP_CANDIDATES.md) documentam estruturas com consumidores estáticos limitados. Uso real, retenção, planos e estatísticas ficaram pendentes | Ausência de uso no código não comprova remoção segura. Repetir com catálogo acessível e janela de observação suficiente |
| A09 | P3 · CONFIRMADO | `apps/web/app/(app)/sugestoes/actions.ts` descartava os tipos já presentes em `packages/db/src/types.ts` | Casts impediam a checagem de operações de escrita. Correção local voltou a usar o contrato tipado |
| A10 | P2 · CONFIRMADO na configuração | As revisões Cloud Run `api-00038-qsf` e `worker-00056-wjk` apontam para `dc69d1fb`, 51 commits atrás da base auditada | O código da `main` e os serviços configurados têm revisões diferentes. Após recuperar a operação, verificar a compatibilidade das migrations e preparar o deploy previsto no projeto |
| A11 | P2 · NECESSITA INVESTIGAÇÃO | `apps/web/proxy.ts` e `apps/web/components/shell.tsx` chamam `auth.getUser()` no caminho autenticado. Nos E2E, o cliente também emitiu avisos sobre a leitura de `session.user` no servidor | Medir as chamadas ao Auth por navegação. Nas leituras examinadas, o ID da sessão serve ao perfil, filtros ou apresentação. A entrada revalida a sessão e as mutações têm autorização própria. Qualquer deduplicação precisa preservar essas garantias e o paralelismo das consultas |
| A12 | P2 · CONFIRMADO no lockfile | Dois avisos de `serveStatic` atingiam Hono e seu adaptador Node. O parser XML usado no worker e pelo SDK do Cloud Storage tinha aviso de consumo quadrático | Atualizados Hono 4.13.11, `@hono/node-server` 2.1.3 e `fast-xml-parser` 5.12.0. API e worker não registram `serveStatic`. Validados o adaptador local e a leitura de XML de NF-e |
